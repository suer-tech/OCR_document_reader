# Повторы пустых обязательных полей RouterAI

Локальное изменение от 2026-11-06. Рабочий API не подключался и не перезапускался.

Политика использует `required: true` из конфигурации полей профиля. Первая попытка
обычная; затем допускаются максимум **три дополнительных раунда**. В каждом раунде
запрашиваются только ещё не заполненные обязательные поля. Пустые необязательные
поля не создают дополнительных запросов. Правила обязательности в YAML не изменены.

Пустые значения: `null`, пустая/пробельная строка, пустые массивы/объекты.
`false`, `0` и строка `"0.00"` не считаются пустыми. Для РТК3 проверяются также
недостающие ячейки обязательной таблицы требований и ошибки подтверждения компонентов.
Наличие строки в правильном формате не заменяет прежние проверки цитат и арифметики.

Общие функции и лимит находятся в `services/field_retries.py`.

- `passport_vision_service`: исходные страницы готовятся один раз; повторная форма
  JSON содержит только пустые обязательные поля и `raw_text`. Полученные значения
  передаются как фиксированный контекст. Неожиданные ключи отклоняются. Неудачный
  дополнительный ответ не уничтожает первый результат. Индекс принадлежит отдельной
  проверке по адресу и не запрашивается этим механизмом у модели.
- `court_selective_llm`: заполненные поля удаляются из следующей формы запроса;
  обязательное пустое поле проверяется до трёх раз дополнительно. Необязательное
  пустое поле принимается как null без дополнительного чтения. После исчерпания
  проверок обязательный null получает `validation_issue`.
- `extraction_agent`: RouterAI-путь РТК/РТК2 и старых агентных профилей повторяет
  только обязательный поднабор полей. Уже полученные поля, включая ИНН кредитора,
  сохраняются в контексте. Старый внутренний цикл пустого кредитора для RouterAI
  не умножает новый бюджет; поле возвращается во внешний ограниченный цикл.
  Исключение исчерпания агентного бюджета не обходится дополнительными попытками.
- `rtk3_evidence`: первая полная схема, затем частичные схемы только нужных фактов.
  Суммы, очереди, полнота и залог проверяются как связанная группа компонентов.
  Обновлённая группа заново проходит `build_fields`, проверки цитат и арифметики.
  Изменение заполненных значений, перестановка строк или ухудшение подтверждённых
  данных отклоняет такую группу. Можно заполнить пустые ячейки без замены известных
  сумм. Неудачный/пустой ответ целиком тоже имеет максимум три дополнительных попытки.
  Независимый корректный факт можно принять даже при конфликте другой группы.

- `bankruptcy_application_llm`: RouterAI Argon сначала получает схему всех 16 полей,
  затем только пустых обязательных. Уже заполненные значения и выбранная цитата
  шапки фиксируются. Иностранный паспорт освобождает серию и код подразделения
  от повторов. Максимум 3 дополнительных раунда; необязательные null не повторяются.
  Ошибки ответа не включают локальный парсер. Здесь используется httpx gateway,
  скрытых повторов SDK нет; повтор организует сам обработчик заявления.
  Для сканов/фото Argon получает исходные изображения в каждом раунде, без
  промежуточного OCR; рендер всех страниц выполняется один раз. Цитаты здесь —
  транскрипция модели, результат дополнительно требует визуальной сверки.
  Argon также заполняет confidence каждого поля (0..1). Низкая оценка не является
  пустым значением и не запускает повтор. При заполнении пропуска принимается
  оценка нового значения; оценки уже заполненных полей сохраняются.

Успешное первое извлечение не делает повторов. Старый локальный парсер заявления
оставлен для экспериментов и в активном извлечении больше не вызывается.
Автоклассификатор и OCR текста — отдельные этапы, не повторы полей.

В сохранённых объектах повторявшихся полей есть внутренний счётчик
`empty_field_retries`. Публичный формат FieldValue не изменён. Логи содержат
номер повтора и список запрошенных полей. После исчерпания пустое обязательное
значение остаётся null; проверки worker/GET/webhook требуют ручной сверки независимо
от общего quality. Там, где прежний профиль уже формирует специальную ошибку,
она сохраняется. Для остальных исчерпание отражается кодом
`required_field_retry_exhausted`.

Это бюджет прикладных повторов полей в одном извлечении. Сетевые повторы SDK и
повтор целого документа воркером остаются отдельными механизмами. Один батч может
восстанавливать несколько пустых обязательных полей без запроса остальных.

## Проверка

Полный локальный набор: 2117 passed, 1 skipped, 2 прежних сбоя GLM (отсутствующие
`ollama_ocr_url` и `glm_ocr_service`). Новые проверки покрывают лимит, required/optional,
пробельные значения, false/0, сокращение следующей схемы, сохранение полученных
значений, ошибки дополнительных ответов, конфликты компонентов и сохранение одного
проверяемого результата worker после четырёх вызовов РТК3.

Локальный replay трёх сохранённых ответов паспортов: 33/33 заполненных значения
сохранились, по одному ответу из мока на документ, новых модельных запросов нет.
Это проверка отсутствия регрессии сохранённых значений, не новая оценка точности OCR.
Поведение повторного чтения новых изображений реальной моделью не оценивалось.
