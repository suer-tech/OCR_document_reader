# Общий модуль определения пола по ФИО

`ocr_platform.services.fio_gender` — независимый от типов документов локальный
модуль. Он не импортирует API, хранилище, модели LLM или обработчики документов.
Использует уже установленную `pymorphy3`; словарь загружается лениво и кэшируется
внутри процесса. Новых зависимостей нет.

Для уже выделенных компонентов ФИО в именительном падеже:

```python
from ocr_platform.services.fio_gender import infer_gender_from_fio

gender = infer_gender_from_fio(first_name="Анна", patronymic="Ивановна")
# "Женский"
```

Результат: `"Мужской"`, `"Женский"` или `None`. Учитываются окончания отчества и
однозначные разборы имени с тегом Name и прежним порогом score>=0.1. Конфликт
признаков или недостаток оснований оставляет `None`. Фамилия не используется;
полный текст ФИО функция сама не разбивает. Выбор нужного человека, нормализация
компонентов и приоритет явно указанного пола остаются ответственностью вызывающего
обработчика. Вывод по ФИО нельзя выдавать за напечатанное в документе значение.

Для буквального признака в исходной форме отчества, включая склонение:

```python
from ocr_platform.services.fio_gender import infer_gender_from_source_patronymic

gender = infer_gender_from_source_patronymic("Ивана Ивановича")
# "Мужской"
```

Этот вход не использует словарь имён. Вызывающая сторона должна заранее привязать
ФИО к нужному человеку и сохранить исходную цитату/координаты. В судебном разборе
все прежние проверки роли должника, конфликтов, прямых указаний пола и offsets
остались на месте. Прежний набор окончаний не расширялся: это рефакторинг без
изменения политики доказательств. Два входа не являются взаимозаменяемыми режимами.

Подключены экспериментальный локальный парсер заявления на банкротство и общая
часть судебного извлечения пола должника. Имя `bankruptcy_application._gender`
сохранено импортным псевдонимом для совместимости, собственной реализации нет.
При рефакторинге его `source=fio_inference`, confidence и reasoning не менялись.
Позднее пользователь переключил активное извлечение заявления на Argon через
RouterAI: теперь пол заявления определяет модель (`source=bankruptcy_llm`),
локальный модуль здесь не вызывается. Судебный обработчик продолжает использовать
общий модуль. См. `BANKRUPTCY_APPLICATION.md`.

Отдельный пакет `NLP-entity-extractor` имеет другой контракт (`masc/femn`) и правила,
влияющие на нормализацию фамилии. Этот рефакторинг не создаёт для него обратной
зависимости от OCR-платформы и не меняет его поведение. Возможное объединение между
самостоятельными пакетами требует отдельного совместимого адаптера/общего пакета.
