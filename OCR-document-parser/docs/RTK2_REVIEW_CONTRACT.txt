RTK2: процесс «РТК. Отзывы» ЕМУ
Контракт уточнён 30.10.2026. Порядок обновления API и worker приведён ниже.

Все прежние поля сохраняются. Добавлены creditor_name и creditor_application_date.
Формат ответа fields.<name> (name/value/reasoning/confidence/source/extraction_method)
и верхнеуровневые поля результата не меняются. Новая миграция БД не требуется:
структурированные результаты хранятся в существующем JSON.

Шесть полей процесса:
case_number: string|null. Основное дело о банкротстве из шапки. Пробелы,
типографские тире и латинская A нормализуются; номер обособленного спора
(Т/2, Т/3, числовые/буквенные хвосты) не включается. Номер исполнительного
документа или ссылка на дело из основной части не заменяет отсутствующий номер шапки.
Двузначный год приводится к 20xx по существующей конвенции сервиса.

decision_date: string|null, ДД.ММ.ГГГГ. Только календарная дата текущего
определения из шапки; даты более ранних актов в описании не используются.
Если дата шапки отсутствует или неоднозначна, возвращается null и ручная проверка.

creditor_name: string|null. Наиболее полное наименование кредитора именно
рассматриваемого заявления, по возможности в именительном падеже. Извлечение
моделью совместно с датой обращения; требуется дословная цитата о требовании.
Reasoning формируется по подтверждённой цитате. Неподтверждённые предположения
модели об уступке, правопреемстве или «первоначальном кредиторе» не переносятся.

creditor_application_date: string|null, ДД.ММ.ГГГГ. Дата обращения именно этого
кредитора с заявлением/требованием. Требуется цитата с кредитором, датой и действием
подачи. Даты должника, публикаций, возражений, определения или рассмотрения не подходят.
Отсутствующая/неподтверждённая дата возвращается как null без вычисления/подстановки.
Уточнение пользователя 30.10.2026: входящая регистрация («вх.», «поступило»,
«зарегистрировано») не заменяет дату подачи. Если известна только входящая дата,
возвращаются creditor_application_date=null и human_review_required=true.
Цитата должна отдельно подтверждать подачу, без смешения с входящей регистрацией.

hearing_date: string|null, ДД.ММ.ГГГГ. Только явно назначенная дата заседания
по текущему требованию из резолютивной части. Без заседания или без явной даты — null.
Запрещено вычисление «дата определения + месяц», подстановка срока отзыва,
возражений или «рассмотреть не позднее». Отсутствие заседания допустимо.

review_required: boolean|null. true — прямая обязанность должника или
финансового/арбитражного управляющего представить отзыв/письменный отзыв,
возражения по требованию либо заменяющие отзыв пояснения. Для пояснений
требуется также смысловая оценка модели с цитатой. false — обязанности нет.
Общие права («вправе») и служебные фразы («отзывы могут быть представлены»)
не означают обязанность. Неоднозначные/условные требования удерживаются как null.
Reasoning содержит конкретную фразу; обязательства из описания прошлых актов не учитываются.

Валидация и совместимость:
Новые поля обязательны в составе результата, но неизвестные значения остаются null.
Если обязательное значение неизвестно, сведения противоречивы или review_required=null,
validation_status=errors, human_review_required=true,
human_review_reason=rtk2_requires_review. Это консервативный маршрут на проверку,
а не выдуманное значение. Правила одинаковы при сохранении, webhook и GET результата.
Старые сохранённые значения не переписываются; при чтении старого результата
новые обязательные поля могут отсутствовать, что будет отмечено как требующее проверки.
Булево false учитывается как заполненное review_required при расчёте качества.

Деплой:
Перенести все изменённые исходники и профиль rtk2.yaml, обновить одновременно
процессы API и worker. Глобальные/удалённые старые инструкции не могут отменить
обязательный блок правил RTK2, добавляемый после инструкций отдельных полей.
Уже сохранённые документы автоматически не перерабатываются; повторное извлечение
оформляется отдельным запуском с новой версией результата. Не перезаписывать историю.
