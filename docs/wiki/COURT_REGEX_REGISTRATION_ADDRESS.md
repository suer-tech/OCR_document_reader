# Адрес регистрации должника: регулярное извлечение

Реализация: `OCR-document-parser/src/ocr_platform/services/court_regex_debtor_registration_address.py`.
Поле `debtor_registration_address` получает только напечатанное значение, связанное с должником. Все кандидаты по-прежнему требуют подтверждения JEV в общем потоке; этот модуль сеть не вызывает.

## Парные окончания шаблона регистрации, 21.10.2026

Метка принимает `зарегистрированного(ой)`, `зарегистрированный(ая)`, `зарегистрирован(а)` и аналогичные окончания с пробелами. Это расширение метки: выбор должника, конфликтов, адреса и исходных координат не менялся. На 355 результат прежний; в контрольной десятке появился кандидат для А76-33485/2025 с полным прежним адресом. Реальный повторный прогон вернул его с source=regex_jev, без LLM для этого поля. У документа сохраняется один LLM-вызов для другого неподтверждённого поля. Протокол — `runs/court_remaining_fields_20261021/` от корня репозитория. Развёртывания нет.

## Расширение привязки после ФИО, 21.10.2026

По поручению пользователя добавлен кандидат из географии непосредственно после
ФИО текущего должника, без обязательной подписи «адрес регистрации». Отсутствие
улицы, дома и квартиры само по себе не исключает частичный адрес. Место рождения,
управляющий, кредитор и доказанный исторический другой должник не становятся его
источником. Кандидат не принимается автоматически: сохраняются цитата, исходные
координаты и обязательное подтверждение JEV.

Выбор учитывает совместимость: более подробная исходная запись может заменить
частичную географию только при совпадении её компонентов. Разные населённые
пункты, дома, квартиры и текущие должники удерживаются как конфликт. Достройка
адреса, склейка фрагментов и выбор только по длине запрещены. Эквивалентная старая
явная запись имеет приоритет над новой привязкой после ФИО.

Дополнительная выборка заморожена до изменения кода: 40 уникальных ранних PDF
из серверной базы, обработанных в мае–августе 2026 года; 24 development / 16 control.
Сентябрь–октябрь исключены по уточнению пользователя. Проверены пересечения с
355 по SHA PDF, текстам и делам; ранее использованный Степное выделен отдельно.
Даты самих актов также проверены: все 40 раньше сентября. Пересечений с 355 по
SHA PDF, исходному и нормализованному тексту, номеру дела (включая /26 и /2026)
нет. Исторические машинные значения не являются ручным эталоном.

одним проверяющим в первой итерации до просмотра отдельных результатов.
Это небольшая проверка источников, не слепой независимый бенчмарк.

Поддерживаются:

- регистрация, проживание, место жительства/пребывания, объединённые метки и отсутствие двоеточия перед явным адресом;
- статусы ИП/гр., несколько девичьих фамилий, Оглы/Кызы, конструкция «Признать несостоятельным (банкротом) ФИО»;
- адрес без метки непосредственно в скобках с индексом после ФИО либо после ИНН/СНИЛС внутри того же идентификационного блока; закрывающая скобка отделяет последующие адреса СРО, имущества и других лиц;
- сравнение повторов г./гор./город, обл./область/области и букв в сокращении СНТ без достройки адреса;
- удаление полных колонтитулов из нормализованного значения с сохранением их в исходной цитате. Отдельная настоящая цифра дома не удаляется;
- отделение даты следующего события, персональных реквизитов и последующих поручений от адреса.

Общий `ignored_historical_debtor_identity_blocks` разрешает исключать метки внутри строго доказанного исторического блока другого человека при согласии текущей шапки и текущего «Признать». Адресный модуль пропускает только эти метки до создания кандидатов, не маскирует исходный текст и не меняет позиции. Противоречащие текущие адресаты акта не отбрасываются.

Адрес суда/управляющего/СРО, место рождения и имущество должника не становятся его адресом регистрации. Разные квартиры, постоянная и временная регистрация по разным адресам и противоречащие текущие должники приводят к отказу. Назначение финансового управляющего само по себе не создаёт нового должника.

Контракт кандидата: `quote == text[start:end]` для исходной строки Unicode; `requires_confirmation=True`. Значение может нормализовать переносы и сервисные вставки, цитата остаётся дословной. Нет обращений к файлам датасета, ручным ответам, справочникам или персональным ID.
